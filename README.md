# Early uptake of guideline-recommended pain, agitation, and delirium assessment in 208 US intensive care units: an all-or-none pattern

**Nyambod FT, Msemakweli JG, Claris A, Onesphore M, Okpanachi V**

Analysis repository | version of 2026-08-21 | manuscript under review at *Journal of Critical Care*

Analysis code for a study of how far US intensive care units had adopted routine
pain, agitation, and delirium assessment in the one to two years following the
2013 clinical practice guideline of the American College of Critical Care
Medicine, using the eICU Collaborative Research Database (2014–2015).

**The outcome is documentation of an assessment, not the occurrence of
delirium.** An electronic record can establish whether a patient was assessed;
it cannot establish how many patients were delirious, because ascertainment
depends on the screening behavior under study. No estimate of delirium
incidence is offered anywhere in this work.

## Headline findings

| | |
|---|---|
| Documented delirium assessment, validated instrument | **11.2% → 21.3%** of stays, 2014 → 2015 |
| Hospitals showing no change (of 173 in both years) | **123** |
| New adopters starting from no assessment of any kind | **12 of 14** |
| Hospitals documenting no validated delirium assessment | **138 of 190 (72.6%)** |
| Intraclass correlation, delirium assessment | **0.936**, unchanged by case-mix adjustment |
| Structural non-adopter fraction | **0.71** (block-bootstrap 95% CI 0.54–0.80) |
| Stays at hospitals with no program at all | **67,545 of 110,257 (61.3%)** |

The aggregate near-doubling came from a small number of hospitals adopting
abruptly, not from the field moving together. Assessment behaves as an
all-or-none institutional property: where it happens it is dense (median 4.3
assessments per ICU day, and not one screened stay in 18,174 had a single
isolated assessment), and where it does not happen it is absent entirely.

## Reproducing the analysis

The data cannot be redistributed. See **[DATA_SOURCE.md](DATA_SOURCE.md)** for
credentialing, the SQL, and how to regenerate `data_private/`.

```bash
# 1. populate data_private/ (see DATA_SOURCE.md)
# 2. install dependencies
Rscript -e 'install.packages(c("data.table","ggplot2","lme4","diptest","sandwich",
                               "lmtest","cobalt","patchwork","officer","flextable",
                               "magick","scales"))'
# 3. run everything
Rscript run_all.R           # full pipeline
Rscript run_all.R --quick   # skip the bootstrap-heavy steps
```

`run_all.R` writes a transcript to `results/run_all.log` and regenerates every
number, table, and figure in the manuscript. Scripts locate the repository root
via the `.projectroot` sentinel, so they run correctly from the root, from `R/`,
or from an IDE with a different working directory.

Tested with R 4.6.0.

## Repository layout

```
sql/                 BigQuery extraction and the label audit
R/                   analysis pipeline, numbered in execution order
R/archive/           superseded scripts, kept for provenance, not run
run_all.R            pipeline runner
docs/                manuscript source and reference list
Journal-of-Critical-Care/          title page, cover letter, highlights, references.bib

data_private/        NOT COMMITTED - patient data, governed by the DUA
results/             NOT COMMITTED - analysis objects and the run log
figures/             NOT COMMITTED - regenerated by R/16_figures.R
docs/TABLES.md       NOT COMMITTED - regenerated by R/12_tables.R
```

**Generated outputs are deliberately absent from version control.** Tables,
figures, and results objects are products of the pipeline rather than source,
and all are reproduced by `Rscript run_all.R`. Committing them would let the
repository and the manuscript drift apart silently, with no signal that they had.
Patient data is excluded for a different and stricter reason: the data use
agreement forbids redistribution.

## Methodological notes

Three decisions in this analysis are unusual enough to flag, each documented in
the script that implements it.

**The median odds ratio is not reported.** With a large share of hospitals at
exactly zero the random-intercept model approaches quasi-separation and the
statistic becomes unstable. The ICC is reported instead.

**Hospitals are not independent.** Hospital identifiers partly encode the
contributing health system, and hospitals with adjacent identifiers share
charting templates (permutation test, 10,000 shuffles, p = 0.0001). Grouping
into signature blocks gives a design effect of 2.79, so the effective number of
independent units is nearer 68 than 190. Confidence intervals for the
non-adopter fraction come from a block bootstrap; the naive hospital-level
interval is about 1.6 times too narrow.

**Screening status cannot be estimated with a hospital random intercept.** It is
constant within hospital, so the random effect absorbs it and the model is not
identified. `14_outcomes.R` uses cluster-robust fixed effects instead and treats
the result as associational only.
